## 協作原則

1. **跨會話可見**：任一會話產出的知識節點、代碼片段、設計決定，都應能被其他會話的子智能體檢索與引用。
2. **不重複建 wheel**：同一個問題在三個會話中只應被解決一次，後續會話直接引用。
3. **梳理清楚**：子智能體之間應能直接接觸對方學過的東西，把碎片化知識梳理成結構化索引。
4. **本地優先**：協作數據存在使用者本機，不上傳、不抓取本地全部數據。

## 知識節點格式（建議）

每個知識節點應包含：
- `id`：唯一識別碼
- `session`：來源會話 ID
- `turn`：來源對話回合
- `content`：內容摘要
- `tags`：標籤（陣列）
- `references`：引用的其他節點 ID（陣列，用於跨會話梳理）
- `created_at`：建立時間
- `updated_at`：最後更新時間

## 接入步驟

每個新會話接入時：
1. 在本目錄增加對應會話的索引檔
2. 匯出該會話已產出的知識節點
3. 與現有節點做交叉參考，建立 `references` 關聯
4. 更新本索引表
